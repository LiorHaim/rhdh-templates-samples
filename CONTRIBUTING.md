# Contributing

Contributions are welcome — issues, fixes, and new examples alike.

## Reporting an issue

Open a GitHub issue and include:

- What you expected to happen, and what happened instead
- Your RHDH / Backstage version (e.g. RHDH 1.9.0)
- Relevant config snippets or logs, with secrets redacted

## Submitting a change

1. Fork the repository and create a branch off the default branch.
2. Make your change. Keep it focused — one concern per pull request.
3. If the repository has tests or a lint step, run them locally before pushing.
4. Open a pull request describing what changed and why.

## Conventions

- Match the formatting and structure of the surrounding files.
- Document any new configuration option in the README.
- Do not commit credentials, tokens, internal hostnames, or customer data.
